> 历史原件（含 ESP32/串口时代内容）见 [archive/延迟测试待验证项.2026-08-06.md](archive/延迟测试待验证项.2026-08-06.md)。

## 测试环境

- 游戏电脑 → 显卡复制输出 → 2K 144Hz 显示器 + 美乐威采集卡

## 已确认结论：美乐威采集卡低延迟配置

### 配置参数（`MWCaptureWrapperPRO.cs`，已验证为最优）

| 参数 | 当前值 | 说明 |
|------|--------|------|
| 通知类型 | `MWCAP_NOTIFY_VIDEO_FRAME_BUFFERING` | 帧**开始**缓冲时通知（低延迟模式） |
| 帧标识 | `iNewestBuffering` | 获取正在缓冲的帧（低延迟模式） |
| `cyParitalNotify` | **0** | 等整帧完成后触发 capture_event |
| DMA 等待 | `INFINITE` | 无限等待，DMA 传输很快 |

### 与官方示例对比

| 参数 | Normal 模式 | LowLatency 模式 | 当前代码 |
|------|-----------|---------------|----------|
| 通知类型 | `FRAME_BUFFERED` | `FRAME_BUFFERING` | `FRAME_BUFFERING` ✓ |
| 帧标识 | `iNewestBuffered` | `iNewestBuffering` | `iNewestBuffering` ✓ |
| `cyParitalNotify` | 0 | 64 | **0** |

### `cyParitalNotify` 详解

**关键结论**：此参数基于**目标输出尺寸**（640×640），而非源帧（2K）。

```
源帧 2560×1440 逐行缓冲到板载内存
        │
        ▼ 当缓冲到第 960 行时（中心区域起始位置）
        │
    ┌───┴───┐
    │ DMA开始从中心区域传输
    │ 每传输 cyParitalNotify 行目标数据
    │ 触发一次 capture_event
    └───────┘
        │
        ▼ 若 cyParitalNotify=64，需要 640÷64≈10 次才能完成
```

**实际测试结果**：
- `cyParitalNotify=0`：while 循环一次就跳出
- `cyParitalNotify=64`：while 循环多次才跳出
- 两者软硬时间几乎没有变化

**结论**：
- `cyParitalNotify>0` 用于"边传输边处理"场景（如视频编码）
- YOLO 检测需要完整图像，**设置为 0 是正确选择**
- 截取中心区域时，必须等源帧缓冲到中间位置（~3.3ms @ 144Hz）

### SDK 参考

- 官方示例：`SDKv3/Examples/Legacy_VC++/GUI/LowLatency`
- `CAPTURE_PART_LINE = 64`（定义在 LowLatencyDlg.h）

### 采集延迟实测结果（2K 144Hz）

- 采集卡软硬总延迟：**~5ms**（`MWGetDeviceTime` 与帧时间戳对比测得）
- 符合理论值（1/144Hz ≈ 6.9ms）
- **结论：采集部分配置已为最优，主要缺口在 YOLO 推理**

## 仍有效的待验证项

### 1. 显卡输出同步性（中优先级）

**疑问**：复制模式下，显示器和采集卡输出是否真正同步？是否存在帧缓冲导致的额外延迟？

**待验证**：
- [ ] 游戏电脑是否开启 VSync？
- [ ] NVIDIA 控制面板"低延迟模式"是否启用？

**测试方法**：关闭 VSync 后重测端到端延迟；启用 NVIDIA "Ultra Low Latency Mode" 对比。

### 2. 网页渲染管线延迟（低优先级）

**疑问**：反应测试网页从"准备变色"到"实际像素上屏"的时间未知，浏览器渲染管线有额外延迟。

**测试方法**：用 C# 写全屏颜色切换程序做同样测试，对比差异；差异大说明网页渲染虚高了端到端数据。

### 3. YOLO 推理性能差异（低优先级，部分过时）

历史现象：同一模型在独立测试程序推理 8.7ms，主项目 10.8-19.5ms。当时怀疑图像转换方式
（`Save→Stream→Image.Load()` vs `WrapMemory<Rgb24>` 零拷贝）与计时口径差异
（`result.Speed.Inference` 纯推理 vs 采集卡硬件时钟含调用开销）。

> 注：主项目推理链路已从 YoloSharp 迁移到 TensorRT（`TrtYoloPoseNativeInferencer`），
> 本条的 ONNX 时代排查手段已过时；当前推理性能问题以 **ISSUE-022**（换卡后推理抖动）为主线跟进。

### 4. 换卡后的推理抖动（当前主线 → ISSUE-022）

RTX5090 → RTX5060 后 YOLO 推理时间偶尔变长，真人模式瞬狙成功率下降。
怀疑方向：engine 在 5090 上构建，5060 未必走最优 tactic；Monitoring 窗口内推理机会少。
验证手段与修复方向见 ISSUES.md ISSUE-022（含测试窗体埋点 `GetPerformance()` 的计划）。
